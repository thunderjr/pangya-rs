# ADR-0015: serve the client's patch web contract from `pangya-updater`

- Status: accepted
- Date: 2026-08-07
- Supersedes: nothing. Triggers the conditional in [`SPEC.md`](../SPEC.md) §13.4.

## Context

[`SPEC.md`](../SPEC.md) §13.4 said:

> PAK/XTEA/updatelist support is Tier D **unless a real client startup path proves it is
> required earlier**.

Running the U.S. 852 client against this server proved it. Before the client opens a single
socket to LoginService it makes three HTTP requests, and failing any one of them ends the
run — with the client's own dialog, not a protocol error:

| Request | Failure mode when missing |
|---|---|
| `GET /Translation/Read.aspx` | "string load failed." and exit |
| `GET …/S4_Patch/updatelist` | "Please re-install the game or run the update program first." |
| `GET …/S4_Patch/extracontents/extracontents.xml` → theme document → every named image | silent exit |

Only after all three does the client mount its PAK series. The `updatelist` is
XTEA-encrypted with a per-region key and its `fcrc` field is a nonstandard CRC-32, so this
is not a contract that can be stubbed: the bytes have to be right.

Separately — and not solvable by any server — the client requires the registry value
`HKLM\SOFTWARE\WOW6432Node\Ntreev USA\Pangya\IntegratedPak`, which retail's updater writes
and a copied install lacks. That is recorded in [`RUNNING_THE_CLIENT.md`](../RUNNING_THE_CLIENT.md).

## Decision

1. **A new crate, `pangya-updater`**, holds the cipher, the checksum, the document layout, and
   the theme/translation documents. It is the optional crate §6.1 already reserved. It has no
   Tokio, SQLx, or packet dependency: the contract is static content, holds no domain state,
   and never queries the database.
2. **A listener of its own**, `[client_web]`, not extra routes on `[http]`. The patch surface
   must be reachable by whatever machine runs the client; health, readiness, and metrics must
   not be. Both keep the loopback default and a non-loopback bind still requires
   `--acknowledge-public-bind`.
3. **Content is prepared at startup, before the listener binds.** Building the update list
   means checksumming the whole client directory — a little over 2.5 GiB for the U.S. series,
   about eight seconds — so it runs on a blocking worker. Doing it eagerly means a
   misconfigured client directory is a startup error with an actionable message instead of
   arriving later as the client's "please re-install the game".
4. **`advertise` is separate from `bind`.** The client passes the theme `url` to WinINet
   verbatim, so a relative path or a container-internal address makes it request a URL with no
   host. This is the same rule as FR-LOGIN-008, for the same reason.
5. **Proprietary content stays operator-supplied.** The translation catalog is the client's own
   localized strings and the theme images are its own assets; the service transports what the
   operator points it at and ships neither.
6. **The algorithms are reproduced exactly, not corrected.** The checksum's table is generated
   from the normal-form constant `0x04C11DB7` treated as reflected, which is not
   CRC-32/ISO-HDLC; the XTEA variant subtracts its delta while encrypting. The client is the
   specification. Both quirks are documented at their definitions so a later reader does not
   "fix" them.

## Consequences

- A real client can complete startup and mount its PAK data against this server. That is a
  precondition for every remaining item on the §19.6 checklist, none of which could be
  attempted before.
- Byte equality with a known-accepted encoder is pinned two ways: a committed golden fixture
  generated by an independent implementation, and a one-off comparison against that
  implementation's output for the real 84-file U.S. PAK directory, which matched exactly.
- `pangya-updater` is ISC-attributed in [`PROVENANCE.md`](../PROVENANCE.md) and
  [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md). No upstream file is vendored.
- This ADR does **not** claim the client reaches its login screen. It does not; see
  [`PROGRESS.md`](../PROGRESS.md) for the open blocker past this point.

## Alternatives rejected

- **Stub the endpoints.** The `updatelist` is a cipher plus a checksum the client verifies;
  an empty or malformed body reproduces the original failure.
- **Merge into the admin listener.** Would publish readiness and metrics to every machine that
  needs a patch manifest.
- **Put it in `pangya-data`.** That crate owns the immutable gameplay catalog behind a
  capability. The patch contract is unrelated content with its own cipher and its own HTTP
  shape, and mixing them would give `pangya-data` an HTTP concern it has no reason to hold.
- **Vendor `pangfiles` as a build dependency.** It is Go, and §20.3 forbids builds that depend
  on the reference clones.
